# Context Arbor

Локальная связанная память проектов для Codex, Claude Code и других coding-агентов.
Она хранится в Markdown-vault Obsidian, не вызывает модель и не требует API-ключей.

Context Arbor не заявляет экономию токенов. Его задача — сохранить полезные решения,
ограничения и состояние разработки без автоматической загрузки всей истории.

## Установка

```sh
python install.py /path/to/project --agents all
```

Либо скопируйте `arbor.py` в проект и выполните:

```sh
python arbor.py init
```

Поддерживаемые адаптеры: `generic`, `codex`, `claude` или список через запятую.
Существующие заметки и инструкции сохраняются. `--force-toolkit` заменяет установленный
`arbor.py`. Старый `handoff.md` при инициализации переносится в `memory/NOW.md`, а
состояние `.ctx/session-state.md` мигрирует в `.arbor/` при первом чтении.

## Память

```sh
python arbor.py memory init
python arbor.py memory query "почему приняли это решение"
python arbor.py memory context "текущая задача"
python arbor.py memory check
python arbor.py memory rotate
python arbor.py memory trace DEC-20260914-003
python arbor.py memory open
python arbor.py memory open --install-obsidian
```

Память разделена на кольца:

- `memory/NOW.md` — горячее кольцо: только активная задача;
- решения, правила, архитектура и исследования — тёплое кольцо;
- `memory/archive/` — холодное кольцо, исключённое из обычного поиска;
- `memory/links.md` — короткие русско-английские якоря и связи между заметками.

Локальный поиск предпочитает горячее кольцо и якоря, исключает архив и шаблоны.
`memory check` сообщает, если `NOW.md` превышает примерно 1500 токенов. Команда
`memory rotate` сразу переносит завершённые `TASK-*` из `NOW.md` в архив.

`memory/architecture.md` — отдельный случай: только самые важные факты о стеке и структуре
проекта (язык, фреймворк, хранилище, границы модулей), на английском, без прозы и без
рассуждений — лимит ~400 токенов, `memory check` сообщает `architecture-too-large`, если файл
разросся. Агент пишет туда (заменяя устаревшую строку, а не дописывая новую) только когда стек
меняется или дополняется, и перечитывает файл только тогда же или по прямой просьбе — не в
каждой сессии.

### Запись из программ

Записями можно управлять из CLI, чтобы память вели и приложения, а не только агент:

```
python arbor.py memory add --type IDEA --title "…" --field Source=chat --json
python arbor.py memory get IDEA-20260921-001 --json
python arbor.py memory list --type IDEA --status idea,in-progress --json
python arbor.py memory update IDEA-20260921-001 --status in-progress
python arbor.py memory close IDEA-20260921-001
python arbor.py memory delete IDEA-20260921-001
```

Кроме `TASK`, `BUG`, `DEC`, `INV` есть типы `IDEA` (идеи → `ideas.md`), `KNW` (знания →
`knowledge.md`) и `CHG` (история изменений → помесячно `history/YYYY-MM.md`). Запись атомарна и
идёт под lock-файлом, поэтому приложение и агент могут писать одновременно.

## Типизированные связи между записями

Записи TASK/BUG/DEC/INV могут указать поле `Relations:` — связь с другой записью по её ID:

```
- Relations: supersedes:DEC-20260914-001, caused-by:BUG-20260910-002
```

Допустимые типы: `supersedes`, `caused-by`, `blocks`, `depends-on`, `relates-to`. Направление
всегда «эта запись → цель». Поле заполняется агентом вручную, как и остальные поля записи — без
модели, без базы данных, без шага извлечения сущностей. `memory check` проверяет неизвестный тип
связи и ссылку на несуществующий ID (в том числе среди архивных записей).

```sh
python arbor.py memory trace DEC-20260914-003
python arbor.py memory trace DEC-20260914-003 --depth 3 --json
```

Команда обходит связи локально в обе стороны — что привело к этой записи и что на неё ссылается —
и печатает цепочку с указанием заметки для каждого узла. Это не полноценный граф знаний: см.
`memory/investigations.md` (INV-20260914-002), почему полный вариант с provenance и извлечением
здесь не оправдан.

## Метод разработки

Принципы из `multica-ai/andrej-karpathy-skills` встроены без постоянной загрузки
исходного skill-файла. Шаблон задачи содержит цель, наблюдаемый результат,
ограничения, допущения, область изменений, следующий шаг и проверку. Подробная
заметка [memory/development.md](memory/development.md) открывается только по запросу.

Это сохраняет четыре полезных свойства: явные допущения, минимальную реализацию,
точечные изменения и проверяемое завершение. Источник отмечает skill как MIT;
интеграция основана на просмотренной версии `2c606141936f1eeef17fa3043a72095b4765b9c2`.

## Сессии

```sh
python arbor.py session save --note "Цель, решения, открытые вопросы, важные пути"
python arbor.py session restore
python arbor.py session snapshot --transcript /path/to/session.jsonl
python arbor.py session gauge --transcript /path/to/session.jsonl
```

Локальное состояние хранится в `.arbor/session-state.md`. Для Claude Code установщик
локально отключает встроенную Auto Memory и подключает только хуки сохранения и
восстановления вокруг штатного сжатия контекста. Настройка записывается в исключённый
из Git `.claude/settings.local.json`; остальные пользовательские параметры сохраняются.
Автоматический снимок извлекает последние запросы и изменённые пути без модели.

## Границы

- Никакая заметка не расходует токены, пока агент её не прочитал.
- Адаптер направляет агента сначала в `NOW.md`; полный vault не сканируется.
- Архив не участвует в стандартном поиске.
- Context Arbor не переписывает сообщения пользователя и не создаёт дополнительные чаты.
- Системный контекст и история текущего чата остаются под управлением оболочки агента.

Для переноса проекта сохраняйте каталог `memory/`. Локальная `.arbor/` исключается
из Git. Публикация или отправка изменений этим инструментом не выполняется.
