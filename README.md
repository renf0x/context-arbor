# Context Arbor

Локальная связанная память проектов для Codex, Claude Code и других coding-агентов.
Она хранится в Markdown-vault Obsidian, не вызывает модель и не требует API-ключей.
Единственное исключение — Jev: он выключен по умолчанию и включается вручную (см. ниже).

Context Arbor не обещает экономию токенов. Его задача — сохранить полезные решения,
ограничения и состояние разработки без автоматической загрузки всей истории, дать агенту
короткие команды вместо чтения файлов целиком и **измерять** расход (`arbor stats`,
`arbor ui`), чтобы результат можно было проверить, а не принять на веру.

## Установка

В новый проект одной командой (из папки проекта):

```powershell
irm https://raw.githubusercontent.com/renf0x/context-arbor/main/install.ps1 | iex
```

```sh
curl -fsSL https://raw.githubusercontent.com/renf0x/context-arbor/main/install.sh | bash
```

Или из клона репозитория:

```sh
python install.py /path/to/project --agents all
```

Либо скопируйте `arbor.py` в проект и выполните:

```sh
python arbor.py init
```

Поддерживаемые адаптеры: `generic`, `codex`, `claude` или список через запятую.
Существующие заметки и инструкции сохраняются. Управляемый блок в `CLAUDE.md`/`AGENTS.md`
обновляется на месте только если он побайтно совпадает с блоком прежней версии Arbor; правки
пользователя внутри блока не трогаются. `--force-toolkit` заменяет установленный
`arbor.py`. Старый `handoff.md` при инициализации переносится в `memory/NOW.md`, а
состояние `.ctx/session-state.md` мигрирует в `.arbor/` при первом чтении.

## Память

```sh
python arbor.py memory init
python arbor.py memory query "почему приняли это решение"
python arbor.py memory context "текущая задача"
python arbor.py memory check
python arbor.py memory rotate
python arbor.py memory trace DEC-20260914-003
python arbor.py memory open
python arbor.py memory open --install-obsidian
```

Память разделена на кольца:

- `memory/NOW.md` — горячее кольцо: только активная задача;
- решения, правила, архитектура и исследования — тёплое кольцо;
- `memory/archive/` — холодное кольцо, исключённое из обычного поиска;
- `memory/links.md` — короткие русско-английские якоря и связи между заметками.

Локальный поиск предпочитает горячее кольцо и якоря, исключает архив и шаблоны.
`memory check` сообщает, если `NOW.md` превышает примерно 1500 токенов. Команда
`memory rotate` сразу переносит завершённые `TASK-*` из `NOW.md` в архив, а если файл всё ещё
больше лимита, сворачивает самые длинные открытые задачи: подробности уезжают в
`memory/tasks/<ID>.md`, в `NOW.md` остаются заголовок, строки Status/Goal/Next/Relations и ссылка.
`NOW.md` читается в начале каждой сессии и после каждого `/clear` и сжатия, поэтому раздутый файл
оплачивается снова и снова (в одном реальном проекте ~8k токенов, ~14 прочтений за пять сессий, ~111k токенов).

Поиск сопоставляет слова, а не смысл: русский вопрос к английским заметкам ничего не найдёт.
Если поиск пуст, а запрос не латиницей, `memory query` подсказывает агенту повторить его
ключевыми словами на языке заметок.

Хуки Claude Code запускаются из корня проекта (`$CLAUDE_PROJECT_DIR`), даже если агент сделал
`cd` в подпапку, и ничего не делают, если `arbor.py` не найден, вместо того чтобы блокировать
сессию. Повторный `python arbor.py init` переписывает хуки старого формата на месте.

`memory/architecture.md` — отдельный случай: только самые важные факты о стеке и структуре
проекта (язык, фреймворк, хранилище, границы модулей), на английском, без прозы и без
рассуждений — лимит ~400 токенов, `memory check` сообщает `architecture-too-large`, если файл
разросся. Агент пишет туда (заменяя устаревшую строку, а не дописывая новую) только когда стек
меняется или дополняется, и перечитывает файл только тогда же или по прямой просьбе — не в
каждой сессии.

### Запись из программ

Записями можно управлять из CLI, чтобы память вели и приложения, а не только агент:

```
python arbor.py memory add --type IDEA --title "…" --field Source=chat --json
python arbor.py memory get IDEA-20260921-001 --json
python arbor.py memory list --type IDEA --status idea,in-progress --json
python arbor.py memory update IDEA-20260921-001 --status in-progress
python arbor.py memory close IDEA-20260921-001
python arbor.py memory delete IDEA-20260921-001
```

Кроме `TASK`, `BUG`, `DEC`, `INV` есть типы `IDEA` (идеи → `ideas.md`), `KNW` (знания →
`knowledge.md`) и `CHG` (история изменений → помесячно `history/YYYY-MM.md`). Запись атомарна и
идёт под lock-файлом, поэтому приложение и агент могут писать одновременно.

## Типизированные связи между записями

Записи TASK/BUG/DEC/INV могут указать поле `Relations:` — связь с другой записью по её ID:

```
- Relations: supersedes:DEC-20260914-001, caused-by:BUG-20260910-002
```

Допустимые типы: `supersedes`, `caused-by`, `blocks`, `depends-on`, `relates-to`. Направление
всегда «эта запись → цель». Поле заполняется агентом вручную, как и остальные поля записи — без
модели, без базы данных, без шага извлечения сущностей. `memory check` проверяет неизвестный тип
связи и ссылку на несуществующий ID (в том числе среди архивных записей).

```sh
python arbor.py memory trace DEC-20260914-003
python arbor.py memory trace DEC-20260914-003 --depth 3 --json
```

Команда обходит связи локально в обе стороны — что привело к этой записи и что на неё ссылается —
и печатает цепочку с указанием заметки для каждого узла. Это не полноценный граф знаний: см.
`memory/investigations.md` (INV-20260914-002), почему полный вариант с provenance и извлечением
здесь не оправдан.

## Карта кода

Токены уходят не только на ответ. Всё, что попало в контекст (файл, прочитанный целиком, широкий
grep), пересылается заново на каждом следующем ходу. Кэш делает это дешевле, но не убирает:
чтение кэша растёт как число ходов × размер контекста. Arbor не управляет кэшем оболочки агента —
он уменьшает то, что умножается.

```sh
python arbor.py code map                       # обзор проекта в пределах бюджета токенов
python arbor.py code find "тема или имя"       # символы и файлы, ранжированные локально
python arbor.py code outline src/app.py        # символы файла с номерами строк
python arbor.py code show src/app.py:Cart.add  # один символ, а не весь файл
python arbor.py code show src/app.py:120-160   # или точный диапазон строк
python arbor.py code refs total_price          # где встречается имя, коротким списком
```

Индекс `.arbor/code-index.json` обновляется сам: при каждом вызове проверяются размер и время
файлов, разбираются только изменённые. Python разбирается через `ast`; JS/TS, Go, Rust,
Java/Kotlin/C#, Ruby, PHP, GDScript (`class_name`, вложенные `class`, `func`, `signal`, `enum`,
`const`, `@export`), shell, PowerShell и Markdown — построчными правилами, то есть
приблизительно, а `code show FILE:START-END` остаётся точным запасным вариантом. Когда проект
слишком велик для обзора с символами, `code map` сворачивает глубокие папки в предков
(«N files, incl. subfolders»), а не печатает стену путей; углубиться можно через `--dir`. Не индексируются
`.gitignore`, секреты (`.env`, `*.pem`, ключи) и хранилище памяти. Большой файл без указания
символа `show` не печатает целиком, а показывает его структуру. Это справка по запросу, а не
запрет на чтение: обычное чтение файлов ничем не блокируется. Агент узнаёт о командах из двух
строк управляемого блока (около 45 токенов на сессию).

## Метод разработки

Принципы из `multica-ai/andrej-karpathy-skills` встроены без постоянной загрузки
исходного skill-файла. Шаблон задачи содержит цель, наблюдаемый результат,
ограничения, допущения, область изменений, следующий шаг и проверку. Подробная
заметка [memory/development.md](memory/development.md) открывается только по запросу.

Это сохраняет четыре полезных свойства: явные допущения, минимальную реализацию,
точечные изменения и проверяемое завершение. Источник отмечает skill как MIT;
интеграция основана на просмотренной версии `2c606141936f1eeef17fa3043a72095b4765b9c2`.

## Сессии

```sh
python arbor.py session save --note "Цель, решения, открытые вопросы, важные пути"
python arbor.py session restore
python arbor.py session snapshot --transcript /path/to/session.jsonl
python arbor.py session gauge --transcript /path/to/session.jsonl
```

Локальное состояние хранится в `.arbor/session-state.md`. Для Claude Code установщик
локально отключает встроенную Auto Memory и подключает хуки сохранения и восстановления.
Настройка записывается в исключённый из Git `.claude/settings.local.json`; остальные
пользовательские параметры сохраняются. Автоматический снимок извлекает последние запросы и
изменённые пути без модели.

### Длинные сессии: сжатие, а не `/clear`

Начинать заново после каждых нескольких задач неудобно, и этого почти никто не делает. Поэтому
Arbor больше не блокирует `/compact` и авто-сжатие, а помогает им: сжатие — обычный путь длинной
сессии (DEC-20261002-001).

- Перед сжатием (`PreCompact`) и при завершении сессии (`SessionEnd`) состояние сохраняется
  детерминированно: последние запросы, изменённые файлы, команды, оставленные в фоне, и последний
  ответ агента.
- После сжатия, `/clear` или в новой сессии (`SessionStart`) оно возвращается вместе с открытой
  задачей из `NOW.md`. Claude Code после сжатия и сам заново подгружает `CLAUDE.md`, поэтому строки
  Arbor (как искать в памяти и коде, что сохранять в резюме) никуда не пропадают. Очистка в
  десктопном приложении открывает новую сессию (`startup`) без `SessionEnd`, поэтому `restore` сам
  снимает состояние с предыдущего транскрипта проекта. На `startup` состояние старше 12 ч не
  подставляется.
- Какие события реально приходят, видно в `.arbor/hook-log.jsonl` (последние 50).

Главное — порог. Сжатие стоит одного вызова модели и перезаписи кэша, а окупается тем, что
каждый следующий ход пересылает меньше. `stats --simulate-compact` переигрывает ваши собственные
журналы с автосжатием на разных порогах. На журналах одного реального проекта (4739 ходов)
дешевле всего вышло окно около 200k: 0,85 от фактической стоимости. Окно 400k дало 1,09, а
стандартное для моделей с окном 1M (~967k) — 2,00. Частые ручные `/compact` со 152k до 109k
почти ничего не давали. Поэтому в Claude Code один раз выполните `/autocompact 200k` (значение
сохраняется в настройках пользователя):

```sh
python arbor.py stats --simulate-compact           # подобрать окно по своим журналам
python arbor.py session compaction                 # напомнить, что настроить (Claude Code и Codex)
```

В Codex то же задаётся параметром `model_auto_compact_token_limit` в `~/.codex/config.toml`.

`gauge` (хук `UserPromptSubmit`) молчит, пока контекст не перерос это окно. Порог считается от
**роста** над первым ходом сессии, а не от абсолютного размера: префикс (системный промпт,
инструменты, `CLAUDE.md`, навыки, MCP) на реальном проекте занимает 60–70k. По умолчанию «на
ближайшей паузе» — после +140k (≈200k при префиксе 60k), «сейчас» — после +240k (≈300k, дальше
стоимость растёт). Агент просит пользователя выполнить `/compact` и один раз задать
`/autocompact 200k`. Если окно уже задано, Claude Code сожмёт контекст раньше и подсказок почти
не будет. Сразу после сжатия последний ход в журнале ещё показывает старый размер, поэтому до
следующего хода `gauge` считает контекст сброшенным.

```sh
python arbor.py session limit                      # показать пороги
python arbor.py session limit --warn 140000 --crit 240000
python arbor.py session limit --stop 400000        # опционально: жёсткий лимит
python arbor.py session limit --stop 0             # выключить жёсткий лимит
```

Длинный автономный прогон не проходит через `UserPromptSubmit`, поэтому `gauge` его не видит:
в измеренной сессии контекст вырос с 68k до 796k за 271 ход. Жёсткий лимит ставит хук
`PreToolUse` (`session guard`): один раз на уровень предупреждает агента, а после лимита
сохраняет снимок и отклоняет вызовы инструментов, кроме `python arbor.py session|memory …`,
чтобы агент остановился и попросил `/compact`. Хук запускает Python на каждый вызов инструмента
(около 0,1–0,15 с), поэтому по умолчанию он не ставится, а появляется и исчезает вместе с
`--stop`.

Версия 0.5 умела блокировать сжатие (`session compaction --mode manual|all`). Эта блокировка
снята: `python arbor.py init` удаляет её хуки из `.claude/settings.local.json`, а старая команда
хука оставлена пустой, чтобы ещё не обновлённые настройки ничего не ломали.

## Токены и хроника

```sh
python arbor.py stats                       # токены из локальных журналов Claude Code
python arbor.py stats --why                 # куда уходит стоимость и что менять
python arbor.py stats --simulate-compact    # что дало бы автосжатие на пороге 150k...967k
python arbor.py stats --prices input=..,cache_write=..,cache_read=..,output=.. --save
python arbor.py ui --title "Имя проекта" --open
```

`stats --simulate-compact [150k,200k,...]` переигрывает каждую длинную сессию так, будто Claude Code
сжимал её сам на заданном пороге (`/autocompact`, настройка `autoCompactWindow`), и сравнивает
стоимость с тем, как сессия прошла на самом деле. Размер сжатия (что остаётся после него, сколько
переписывается в кеш, длина сводки) берётся из ваших собственных сжатий, если они были. Не учтено:
файлы, которые агент перечитает после сжатия, и потеря деталей в сводке.

`stats` читает из журналов сессий только счётчики токенов и метки времени, дедуплицирует
сообщения и показывает, какая доля входа — чтение кэша, а также самые тяжёлые сессии. Цены
Arbor не встраивает (они меняются и зависят от модели): укажите их сами в USD за миллион токенов,
и появится оценка стоимости; без цен выводятся только токены.

`stats --why` для каждой длинной сессии (от 20 ходов) разбирает стоимость на то, на что проект
может повлиять: сжатия (сколько их, ручные или автоматические, на сколько каждое уменьшает
контекст, сколько переписывает в кэш и за сколько ходов эта запись окупится), время при контексте
на 200k+ выше стартового, долю фиксированного префикса и токены thinking, — и печатает по
каждому пункту, что изменить. Без цен стоимость в относительных единицах (вход = 1, запись кэша на
1 час = 2, чтение кэша = 0,1, вывод = 5), с `--prices` — в USD. Журнал после каждого сжатия
переписывает всю историю заново (файл на 2 ГБ может состоять из повторов), поэтому записи
дедуплицируются и по `uuid`, и по id сообщения. Вызов модели, который пишет само резюме
при сжатии, в журнале не виден и в стоимость не входит.

## Что показали измерения на одном реальном проекте

Godot/GDScript-проект, 5 сессий, 4 747 ходов (две сессии — 98%), локальные журналы, относительные
единицы; это оценки по одному проекту, а не обещание экономии.

- Чтение кэша — 98% входа. Контекст в среднем 163k и 281k при фиксированном префиксе 63–68k;
  префикс — 21–33% стоимости, а не почти весь контекст, как в коротких задачах бенчмарка.
- В большой сессии было 102 ручных `/compact` (каждые ~33 хода): контекст падал лишь со 152k до
  109k, а первый ход после сжатия заново писал в кэш ~66k. Это около 29% стоимости сессии.
- Один прогон без сжатия дорос с 68k до 796k за 271 ход; 40% стоимости той сессии пришлось на
  ходы с контекстом от 400k.
- Токены thinking остаются в контексте и перечитываются каждый ход (11–19% стоимости). Arbor
  этого не меняет: это настройка усилия модели.
- Собственный вклад Arbor (управляемый блок `CLAUDE.md`, вызовы `arbor`, чтения `NOW.md`) — около 1%.
- Поиск по коду в этой работе сильно не поможет: агент и так читает узкими срезами (медиана
  36–41 строка), точные повторные чтения — около 2%, а замена чтения целых файлов на `outline` +
  один символ дала бы по верхней оценке 1–3% стоимости.
- Переигровка тех же журналов (`stats --simulate-compact`): автосжатие на окне 200k — 0,85 от
  фактической стоимости, на ~967k по умолчанию — 2,00. На новых живых сессиях ещё не проверено.

`ui` собирает одну самодостаточную страницу `.arbor/ui/index.html` из заметок памяти, `git log`
и (если есть) журналов сессий: столбчатую диаграмму активности по дням (столбец — день, высота —
число событий, цвет — вид события, клик ведёт к главе дня), главы по дням, вес колец памяти
относительно лимитов, дуги типизированных связей, токены (числа, доли и полоса состава) и сводку
карты кода. Заголовки дней выбирают правила, а не модель; страница не обращается к сети и не
содержит внешних ресурсов. Язык — `--lang ru|en`.

## Веб-интерфейс в любом проекте

`arbor.py` самодостаточен, поэтому интерфейс работает в любом проекте, где Arbor установлен
(см. «Установка»). Из папки проекта:

```sh
python arbor.py ui --open                 # статичная страница .arbor/ui/index.html
python arbor.py ui --serve --open         # то же через локальный сервер + настройки Jev
```

`--serve` поднимает сервер только на `127.0.0.1:8765` (порт меняется `--port`), его не видно из
сети; остановка — Ctrl+C. Страница пересобирается при каждом открытии. Форма защищена токеном,
который живёт до остановки сервера, и проверками `Host`/`Origin`, так что посторонний сайт не может
отправить в неё данные. Статичная страница показывает только состояние Jev, без формы.

## Jev: память, которая находит заметки сама (по желанию)

Перед каждым вашим сообщением хук спрашивает у Jev (`~typesafe/jev-latest`, Decisions API
OpenRouter: только вероятности, без генерации текста), какие заметки `memory/` относятся к запросу,
и кладёт до двух подходящих агенту в контекст. Это работает и между языками: вопрос по-русски,
заметки по-английски. Тест co-mem (6 вопросов × 3 прогона, sonnet): чтение памяти — 60 токенов
за прогон вместо 2 290, контекст на 54% меньше, чем без Arbor; точность та же (1,00 против 0,97);
сам Jev стоил около $0,0004 за вызов и ~0,9 с. Ограничения теста — в `memory/investigations.md`
(INV-20261001-004): шесть вопросов, на которые ответ точно есть в памяти.

Включение в проекте:

1. `python arbor.py ui --serve --open`, раздел **Jev**: вставьте ключ OpenRouter → «Сохранить
   ключ» → «Включить Jev». То же из терминала: `python arbor.py jev key`, затем `python arbor.py jev on`.
2. Перезапустите сессию агента, чтобы он подхватил новый хук.

Ключ шифруется для текущей учётной записи ОС (Windows — DPAPI, macOS — Keychain, Linux —
Secret Service через `secret-tool`) и хранится вне проекта, поэтому вводится один раз на
компьютер и действует во всех проектах. В Git, в `.arbor/` и в журналы он не попадает. Переменная
`OPENROUTER_API_KEY` имеет приоритет над сохранённым ключом. `/clear` ключ не трогает: он
живёт на диске, а восстановление сессии сообщает агенту, что Jev включён.

```sh
python arbor.py jev status            # вкл/выкл, есть ли ключ (последние 4 символа), расход за день
python arbor.py jev ask "вопрос"      # какие заметки Jev сопоставит вопросу
python arbor.py jev off               # выключить и убрать хук
python arbor.py jev key --clear       # удалить ключ
```

Настройки — в `.arbor/config.json`, ключ `"jev"`: `threshold` (0.2), `top` (2),
`daily_cap_usd` (0.5; после лимита вызовов нет до завтра), `timeout` (10 с). Что уходит на
OpenRouter: текст сообщения и заголовки заметок; тексты заметок остаются на компьютере. Журнал
`.arbor/jev-log.jsonl` хранит стоимость и выбранные заголовки, но не текст сообщений. Любая
ошибка, таймаут или отсутствие ключа — хук молчит, и сессия идёт как без него.

## Границы

- Никакая заметка не расходует токены, пока агент её не прочитал.
- Адаптер направляет агента сначала в `NOW.md`; полный vault не сканируется.
- Архив не участвует в стандартном поиске.
- Context Arbor не переписывает сообщения пользователя и не создаёт дополнительные чаты.
- Системный контекст и история текущего чата остаются под управлением оболочки агента; Arbor не
  управляет её кэшированием и не может его отключить.
- `stats` и `ui` только читают локальные журналы и ничего не отправляют; они измеряют расход, но
  не обещают экономию.
- В сеть ходит только Jev, и только если вы его включили и задали ключ.

Для переноса проекта сохраняйте каталог `memory/`. Локальная `.arbor/` исключается
из Git. Публикация или отправка изменений этим инструментом не выполняется.
